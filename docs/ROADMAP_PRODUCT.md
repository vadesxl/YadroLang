# План развития продукта (Yadro Guard → коммерческий инструмент)

Цель: инструмент, который до запуска AI-агента доказывает и чинит утечки
чувствительных данных, выдаёт красивый отчёт и встраивается в дашборд Hermes.

## Что уже есть
- Анализатор потоков с метками (ПДн, Финансы, Здоровье, Учётные, Локация).
- Правила соответствия метка↔обёртка (КОМПЛАЕНС): шифр для финансов, и т.п.
- CLI `yadro-guard`: scan/audit/compile/policy, коды выхода, JSON/SARIF.
- HTML-отчёт офлайн: вердикт, метки, путь данных, Карантин, подсветка кода.
- 52 регрессионных теста утечек (корпус).

## Этап 1 — Доверие к движку (КРИТИЧНО, в работе)
- Закрыть 17 подтверждённых дыр (печать, возвраты, неявные потоки, циклы).
- Починить 11 некорректных тестов корпуса.
- Все 52 + базовые тесты зелёные на обоих репозиториях.
- Движок должен отдавать ТОЧНЫЙ путь утечки (сейчас в отчёте он эвристический).

## Этап 2 — Автоисправление «было/стало» (начато)
- `src/autofix.py`: по диагностике предложить обёртку и переписанный код.
- Режимы: показать diff (безопасно) и `--apply` (записать в файл).
- Diff встроить в HTML-отчёт блоком «Было / Стало».
- Тесты: исправленный код проходит scan с кодом 0.

## Этап 3 — Карантин-хранилище (токены вместо секретов)
- Модуль `src/vault.py`: секрет → токен (например `ЯДРО-ТОКЕН-ab12…`), который
  хранится отдельно; наружу уходит только токен.
- В языке — обёртка `токенизировать(...)`, уже снимающая метку; vault даёт
  реальное хранилище и обратный обмен токен→секрет по запросу с мандатом.
- Формат хранилища: локальный зашифрованный файл, без облака.
- Отчёт показывает: «секрет заменён на токен, оригинал в карантине».

## Этап 4 — Интеграция в Hermes Orbit
- `src/report_html.py::виджет(...)` — фрагмент в стиле Hermes (палитра/подписи).
- Способ встраивания уточнить по исходникам плагина (папка Hermes сейчас пуста):
  вероятно iframe `srcdoc` или контейнер-карточка.
- Виджет «YADRO GUARD»: статус последнего скана, число утечек, кнопка «открыть отчёт».
- CLI-режим `yadro-guard widget <src> -o widget.html` для вставки.

## Этап 5 — Сканер реального кода (не только .яд)
- Проверять MCP-конфиги и Python-агентов, а не учебный язык.
- GitHub Action: SARIF → вкладка Security в репозитории.
- Публичный бенчмарк утечек как эталон отрасли.

## Этап 6 — Упаковка и продажа
- Переименование (бренд), PyPI, домен, README со сравнением с конкурентами.
- Платная услуга: аудит MCP/агентов этим инструментом (быстрые первые деньги).

## Принципы
- Fail-closed: сомнение = блок.
- Офлайн, без токенов к чужим API, без запуска чужих серверов.
- Каждая найденная дыра → корневая правка + тест (корпус только растёт).
